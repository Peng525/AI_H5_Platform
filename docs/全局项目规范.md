## 3. 技术架构基准

- 本项目采用前后端同仓、单 Docker 镜像交付的模块化单体架构。
- 前端构建产物由后端 FastAPI 静态托管，详见 `develop/docs/系统架构.md`。
- 后端业务接口统一位于 `develop/backend/app/api/`，业务逻辑优先下沉到 `develop/backend/app/services/`。
- 数据库使用 SQLite，运行时数据库位于 `develop/data/`，不得提交真实运行数据。
- 第三方能力包括 LLM、支付、短信、验证码，应通过后端 service/provider 适配层封装。
- `develop/ppt-master-main/` 是 PPT 生成参考子项目，除非任务明确要求，不得把它作为 H5 平台运行时代码改动。

## 4. UI 与前端基准

- 组件体系：Element Plus 负责按钮、表单、输入框、选择器、表格、弹窗、抽屉、导航、分页、提示等基础交互组件。
- 业务组件：`frontend/src/components/` 只封装业务组合组件、编辑器组件和 Element Plus 之上的二次组合，禁止重复自研基础按钮、输入框、弹窗、表格等通用组件。
- 样式体系：Tailwind CSS + `frontend/src/style.css` 负责页面布局、间距、响应式、自定义业务区块和少量业务视觉样式，不重复实现 Element Plus 已提供的基础交互组件。
- 主题体系：Element Plus 主题变量统一在 `frontend/src/styles/element/index.scss` 中维护，Tailwind 颜色与间距应与该主题保持一致。
- 图标体系：Element Plus 原生图标用于 Element Plus 组件生态内的通用操作；Material Symbols 继续用于编辑器、画布、业务功能中的图标补充。
- 页面组件放在 `frontend/src/views/`，公共组件放在 `frontend/src/components/`。
- 接口请求必须通过 `frontend/src/api/client.js` 或 API 层封装调用，禁止页面里散落原生请求。
- 新增或修改 UI 时基础交互组件优先使用 Element Plus，不得私自替换组件体系或大幅改变交互基准。

## 5. 命名规范

- Vue 页面和组件文件使用大驼峰命名，例如 `EditorPhoneCanvas.vue`。
- JavaScript 变量和函数使用小驼峰命名，例如 `slideList`、`handleSave`。
- 常量使用全大写加下划线，例如 `MAX_SLIDE_COUNT`。
- 路由路径使用小写和短横线。
- Python 模块使用小写加下划线。
- Git 提交信息使用约定式提交：`feat:`、`fix:`、`docs:`、`style:`、`refactor:`、`config:`、`chore:`。

## 6. 开发铁则

1. 所有代码修改必须对应明确需求、任务卡或用户当前指令，禁止自行新增未提及的功能、优化或重构。
2. 禁止擅自修改技术栈、全局架构、接口契约、数据库核心结构、UI 基准；确需变更必须先明确说明影响并获得确认。
3. 禁止提交 `.env`、API Key、JWT 密钥、证书、私钥、收款敏感信息、运行时数据库等敏感内容。
4. 接口变更必须同步更新 `develop/docs/功能开发说明书.md` 或对应迭代文档，前后端字段必须保持一致。
5. 需求变更必须先更新需求或任务文档，再进入开发实现。
6. 部署、环境变量或启动方式变更必须同步更新 `develop/docs/部署说明.md` 和 `.env.example`。
7. 禁止为了“更优雅”重构未要求修改的代码；只处理当前需求明确范围。
8. 完成交付前必须执行与变更范围匹配的验证，并在交付说明中写清验证结果。

## 8. Agent 协作规则

### 产品架构 Agent

- 必须遵守 `develop/docs/产品架构agent.md`。
- 负责需求澄清、影响评估、任务拆解、验收标准、迭代计划和文档一致性。
- 不直接编写业务代码，不干预代码层具体实现细节。

### 全栈开发 Agent

- 必须遵守 `develop/docs/全栈开发agent.md`。
- 负责前端、后端、接口、数据库、部署配置的具体实现与验证。
- 不擅自修改需求、架构、接口契约、UI 基准或技术栈。

### 共同要求

- 两类 Agent 都必须先读取 `AGENTS.md` 和本文件。
- 发现规范冲突时，先按本文件执行，并在交付说明中指出冲突点。
- 发现需求不清时，先补充任务卡或验收标准，再进入开发。

## 9. 验证要求

根据变更范围选择最小但有效的验证：

```bash
# 前端测试
cd develop/frontend
npm run test

# 前端构建
cd develop/frontend
npm run build

# 后端语法检查
cd develop/backend
python -m compileall app

# Docker 构建
cd develop
docker build -t ai-h5-platform:local .
```

涉及主流程、部署或跨端联动时，优先使用 Docker 构建或本地完整启动验证。

## 10. 安全与数据边界

- `.env` 只允许本地或服务器保存，禁止提交。
- `.env.example` 只能放示例值和空占位，禁止真实密钥。
- `develop/data/`、SQLite 数据库、支付素材、证书目录中的敏感内容不得随意提交。
- 日志和错误信息不得暴露密码、Token、API Key、验证码密钥或完整私密配置。
- 管理端、支付、配额、LLM 调用相关变更必须优先考虑权限、幂等和异常路径。
