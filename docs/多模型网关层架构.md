# 多模型网关层架构

> 最后更新：2026-08-07

## 设计目标

用**单一接口**屏蔽底层模型差异，使业务层无需关心调用的是中转 API 还是官方 API、是 Gemini 还是 GPT、是免费档还是 Pro 档。

## 整体架构

```
业务层 (deck_generation_service.py)
  │
  ├─ chat_completion(messages, channel, tier, model)
  │    │
  │    ├─ channel="auto"  → chat_auto()  ─┬→ chat_official() ─┬→ 同一个底层函数
  │    │                                    └→ chat_relay()    ─┘ _chat_openai_compatible()
  │    │
  │    ├─ channel="official" → chat_official()
  │    └─ channel="relay"    → chat_relay()
  │
  └─ generate_image(prompt, channel, tier, ...)
       │
       └─ _generate_on_channel() → /images/generations 或 /chat/completions
```

## 三层抽象

### 第一层：统一入口

业务代码只需调用两个函数，无需关心底层细节：

```python
# 文本生成
from app.services.llm import chat_completion
raw, channel, model = await chat_completion(
    messages,           # [{"role": "system", "content": "..."}, ...]
    channel="auto",     # "auto" | "relay" | "official"
    tier="free",        # "free" | "pro"
    model=None,         # None=按档位自动选模型
)

# 图片生成
from app.services.llm.image_provider import generate_image
url, channel, model, width, height = await generate_image(
    prompt="画面描述",
    channel=None,
    tier="free",
)
```

返回值始终包含**实际使用的通道和模型名**，便于日志记录。

### 第二层：通道路由

| channel 值 | 行为 |
|-----------|------|
| `auto` | 按 `llm_auto_order` 顺序尝试可用通道，失败降级 |
| `relay` | 使用中转 API（`llm_relay_base_url` + `llm_relay_api_key`） |
| `official` | 使用官方 API（`llm_official_base_url` + `llm_official_api_key`） |

`auto` 模式的降级逻辑（`_resolve_auto_order`）：

```
读取 llm_auto_order（如 "official,relay"）
  → 过滤：只保留已配置（API Key 非空）的通道
  → 按顺序尝试：先 official → 失败 catch LlmError → 再 relay
  → 全部失败 → 抛出 LlmError("auto 模式全部通道失败")
```

### 第三层：统一协议

所有通道走 **OpenAI-compatible 接口**：

```python
# 所有通道最终调用同一个函数
async def _chat_openai_compatible(base_url, api_key, model, messages):
    url = normalize_url(base_url) + "/chat/completions"
    payload = {"model": model, "messages": messages, "temperature": 0.7}
    resp = await httpx_client.post(url, headers=auth_header, json=payload)
    return data["choices"][0]["message"]["content"]
```

`_normalize_openai_base_url` 自动补全 `/v1` 后缀：

```
https://us.novaiapi.com    → https://us.novaiapi.com/v1
https://api.openai.com/v1   → https://api.openai.com/v1（不变）
```

## 模型分档路由

`model_tier.py` 根据用户会员档位自动选择模型：

```python
# tier → 模型映射
resolve_text_model("free")   → llm_model_free   = "gemini-3.1-flash-image-preview"
resolve_text_model("pro")    → llm_model_pro    = "gemini-3-pro-image-preview"
resolve_image_model("free")  → llm_image_model_free = "gemini-3.1-flash-image-preview"
```

> `resolve_image_model` 固定返回免费档模型（`gemini-3.1-flash-image-preview`），
> 因为该模型已具备多模态生图能力，无需升级。

模型覆盖规则（优先级从高到低）：

1. 调用方显式传入 `model` 参数 → **直接使用**（最高优先级）
2. 通道路由的内部设置（如 `llm_relay_model`）→ 通道级覆盖
3. 档位解析 `resolve_text_model(tier)` → 默认兜底

## 配置体系

`config.py` 通过 `pydantic-settings` 从 `.env` 文件读取：

| 环境变量 | 默认值 | 用途 |
|----------|--------|------|
| `LLM_DEFAULT_CHANNEL` | `auto` | 默认调用通道 |
| `LLM_AUTO_ORDER` | `official,relay` | auto 模式的尝试顺序 |
| `LLM_TIMEOUT` | `120.0` | HTTP 请求超时（秒） |
| `LLM_RELAY_BASE_URL` | `""` | 中转 API 基地址 |
| `LLM_RELAY_API_KEY` | `""` | 中转 API 密钥 |
| `LLM_RELAY_MODEL` | `gemini-3.1-flash...` | 中转通道默认模型 |
| `LLM_OFFICIAL_BASE_URL` | `https://generativelanguage.googleapis.com/v1beta/openai` | 官方 API 地址（默认 Gemini） |
| `LLM_OFFICIAL_API_KEY` | `""` | 官方 API 密钥 |
| `LLM_OFFICIAL_MODEL` | `gemini-3.1-flash...` | 官方通道默认模型 |
| `LLM_MODEL_FREE` | `gemini-3.1-flash...` | 免费档文稿模型 |

| `LLM_IMAGE_MODEL_PRO` | `gemini-3-pro...` | 升级档生图模型 |

## 错误映射

```python
class LlmError(Exception):
    """大模型调用异常：API 失败、响应格式异常等 → API 层返回 502"""

class QuotaLlmError(LlmError):
    """配额不足 → API 层返回 402（触发前端展示充值入口）"""
```

业务层映射（`projects.py`）：

```python
try:
    project = await asyncio.wait_for(
        generate_deck_from_ai(db, user, body),
        timeout=90.0,
    )
except asyncio.TimeoutError:
    raise HTTPException(504, "生成超时（90秒）")
except QuotaLlmError as exc:
    raise HTTPException(402, str(exc))
except LlmError as exc:
    raise HTTPException(502, str(exc))
```

## JSON 提取

`extract_json()` 处理 LLM 返回的不规范 JSON：

```
1. 尝试从 ```json ... ``` 代码块中提取
2. 尝试从第一个 { 到最后一个 } 提取
3. strict=False 允许 JSON 字符串中的控制字符
4. 全部失败 → 抛出 LlmError("无法解析大模型返回的 JSON")
```

## 图片生成管线

`image_provider.py` 支持三种调用策略（自动切换）：

| 策略 | API 端点 | 条件 |
|------|----------|------|
| `/images/generations` | DALL-E 风格生图 | 无参考图，先尝试 |
| `/chat/completions`（多模态） | Gemini 风格 `modalities: ["image","text"]` | 有参考图 或 images 端点失败 |
| `/chat/completions`（含 aspect_ratio） | 带 `image_config` 的生图 | 横屏/竖屏场景 |

宽高比自动计算：

```python
# viewport 尺寸 → API 宽高比
ratio = w / h
ratio < 0.85  → "9:16"（竖屏）
ratio > 1.15  → "16:9"（横屏）
其他          → "1:1"（方形）
```

## API 路由

| 端点 | 用途 | 网关函数 |
|------|------|----------|
| `POST /api/v1/项目/ai-生成` | 全量生成演示 | `chat_completion()` + `generate_image()` |
| `POST /api/v1/项目/{id}/页面/ai-生成` | 单页生成 | `chat_completion()` |
| `POST /api/v1/项目/{id}/生成/配图` | 单张配图 | `generate_image()` |
| `POST /api/v1/生图/独立` | 独立生图 | `generate_image()` |

## 调用链路示例（全量生成）

```
POST /api/v1/项目/ai-生成 { topic: "新能源汽车", page_count: 10, strict_template_mode: true }
  │
  ├─ projects.py: ai_generate_project()
  │    │ body.strict_template_mode = True  ← 强制开启
  │    │ asyncio.wait_for(..., timeout=90) ← 硬超时
  │    │
  │    └─ deck_generation_service.py: generate_deck_from_ai()
  │         │
  │         ├─ render_template("严格模板生成.yaml", vars)  ← Jinja2 渲染 Prompt
  │         ├─ chat_completion(messages, channel, tier)    ← 文本生成
  │         │    └─ channel="auto" → chat_auto()
  │         │         ├─ try chat_official() → Gemini API
  │         │         │    └─ _chat_openai_compatible(base_url, key, model, messages)
  │         │         │         POST /chat/completions (httpx, timeout=120s)
  │         │         │         → "choices"[0]["message"]["content"]
  │         │         └─ fail → try chat_relay() → 中转 API
  │         │
  │         ├─ extract_json(raw)  ← 解析 LLM 返回的 JSON
  │         ├─ _normalize_strict_slide()  ← 规范化为 structured dict
  │         ├─ _enrich_strict_images()    ← Unsplash/Pexels 搜索配图
  │         └─ seed_project_slides()      ← 写入 DB
  │
  └─ return ProjectOut (含 slides + settings)
```

## 安全模型覆盖

调用方可以通过 `model` 参数临时覆盖默认模型：

```python
# 前端传入 model 参数（管理端高级选项）
body.model = "gpt-5.5"
# 网关层优先使用，不走档位解析
chat_completion(messages, channel="auto", model="gpt-5.5")
```
