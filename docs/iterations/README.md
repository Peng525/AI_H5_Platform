# 迭代文档 README

本目录用于归档敏捷迭代阶段的计划、任务卡、验收记录和变更说明。每次进入新一轮功能开发或优化时，先由产品架构 Agent 在这里创建对应迭代目录，再交给全栈开发 Agent 执行。

## 目录命名

每个迭代使用独立目录：

```text
sprint-001-功能名/
├── 迭代计划.md
├── 任务卡.md
└── 验收记录.md
```

命名规则：

- `sprint-001`：三位递增编号
- `功能名`：简短中文或英文短横线名称
- 一个迭代目录只承载一组目标一致的任务

## 迭代计划必备内容

- 迭代周期与目标
- 任务清单：任务 ID、任务名称、优先级、依赖、影响范围
- 交付物清单：代码、文档、配置、资源
- 验收标准
- 风险与待确认项

## 任务卡要求

任务卡必须使用 `develop/docs/templates/任务卡模板.md` 的结构，至少包含：

- 任务 ID
- 任务名称
- 需求描述
- 验收标准
- 关联文档
- 影响范围
- 优先级

## 状态管理

建议状态：

- `待确认`：需求或验收标准仍需补充
- `待开发`：可交给全栈开发 Agent
- `开发中`：正在实现
- `待验收`：已完成实现，等待验证
- `已完成`：验收通过
- `已暂停`：因外部依赖或需求变更暂停

## 使用原则

- 先更新文档，再开发。
- 一个任务只解决一个明确问题。
- 每条验收标准必须可验证。
- 需求变更必须更新对应迭代文档并保留变更说明。
